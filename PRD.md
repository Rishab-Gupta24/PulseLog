# Product Requirements Document (PRD) — PulseLog

## 1. Product Overview
**PulseLog** is an offline-first personal health and workout tracker built with React Native (Expo) and local SQLite. It consolidates resistance training logs, approximate meal and macro logging, scale weight trends, and step tracking into a single, fast mobile interface without paywalls or AI hype.

## 2. Problem Statement
1. **App Fragmentation:** Users typically juggle separate apps for lifting sets, meal tracking, and weight/step trends, while basic logging tools are often locked behind monthly subscriptions.
2. **False Precision & Onboarding Friction:** Traditional calorie trackers demand exact gram weights on a food scale and force users through rigid calorie-goal calculators before they can log a single workout or meal. Meanwhile, many fitness apps present rough formulas as exact measurements or alter user targets automatically without context.

## 3. Core Product Principles
* **Optional, User-Chosen Targets (Zero Forced Setup):** Users can skip target setup entirely and use PulseLog purely as a logbook. Targets for calories, macros, and steps are completely optional—users can set all, some, or none of them anytime in Settings. When a target is set, the UI shows progress toward that goal; when unset, the UI simply displays the daily logged total without a progress bar. The app never automatically mutates targets based on formulas or weight trends.
* **Transparent Estimates & Explicit Inputs:** Rough workout MET presets and portion-based meal logs (`Small / Medium / Large`, `1 Fist`, `1 Palm`, `1 Thumb`) are approximations, not clinical measurements. Every calorie burn and nutrition view must clearly label values as **Approximate Estimates** and show the underlying assumptions (such as the MET preset and body weight used).
* **Unified Local-Timezone Date Rule:** All daily logs and "Today" dashboard summaries use a single canonical `YYYY-MM-DD` date string calculated in the user's **local device timezone** (never raw UTC `.toISOString()` slicing) so logs around midnight and edits to older dates behave consistently.
* **Local-First Storage with Explicit Data Safety:** All logs live in an on-device SQLite database for offline reliability. Because uninstalling a local-only app erases data, v1 includes full **JSON Export & Import** with pre-restore validation, an explicit destructive-replace confirmation dialog, and an exclusive database transaction.
* **Functional Utility & Automated Testing First:** Core logging, editing, deleting, charting, and automated behavioral tests come first. Visual polish (Liquid Glass navigation chrome and a portfolio showcase website) is strictly deferred until the core mobile app is working and verified.

## 5. Verification, Testing & CV Standards
* **Automated Behavioral Tests:** Core business logic—local date formatting, 7-day moving average math, workout CRUD & MET calculation (strictly `logged_date <= workout_date` with `NULL` fallback), staple/custom meal portion math, backup JSON validation/restore, and step-permission fallback/conflict rules—must be covered by automated Jest tests.
* **No Unverified Claims:** Performance numbers (such as SQLite query latency) and native integration claims (HealthKit / Health Connect) must only be documented on a CV or README after being implemented, tested on a physical device, and measured using `performance.now()`.
