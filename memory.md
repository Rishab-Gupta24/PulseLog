## 2. Architectural Decision Records (ADRs)
* **ADR-001 (Non-AI Offline-First Focus):** Removed the paid AI Coach, ad networks, and cloud Vision APIs. Focusing on local SQLite storage, clean relational CRUD, moving-average math, automated tests, and native health permissions produces a verifiable mobile engineering project.
* **ADR-002 (Version-Agnostic Expo Setup):** Standardized on the current stable Expo SDK and `npx expo install` rather than hardcoding an older SDK floor.
* **ADR-003 (Optional, Nullable User Targets):** Made all target fields in `user_targets` nullable and onboarding skippable so users can log workouts, meals, weight, or steps immediately without forced goal setup.
* **ADR-004 (Strict Prior/Same-Day Weight Lookup for MET Estimates):** Resolved the earlier contradiction—workout calorie estimates strictly query `logged_date <= workout_date`. Removed the future-weight fallback so past workouts are never calculated using weights logged days later. If no weight exists on or before `workout_date`, `estimated_calories_burned` is `NULL`.
* **ADR-005 (Explicit Staple Reference Servings & Custom Meal Multipliers):** Defined `StapleFoodItem` with a concrete `1.0x` reference serving, base macros, and portion multipliers (`Small 0.75x`, `Medium 1.0x`, `Large 1.5x`, `0.5/1/2 Fist/Palm/Thumb`), plus custom meal entry storing `base_*` and `portion_multiplier` on `meal_logs` so edits recalculate cleanly.
* **ADR-006 (Unified Local-Timezone Date Rule):** Standardized all daily logs (`workout_date`, `logged_date`) on local `YYYY-MM-DD` strings via `toLocalDateString()` (`src/utils/dateUtils.ts`) and local midnight-to-midnight boundaries, preventing UTC date shifts around midnight.
* **ADR-007 (Step Deduplication & Conflict Precedence):** Native step imports use OS-aggregated daily totals (`HKStatisticsOptionCumulativeSum` / Health Connect `aggregateRecord`) to avoid multi-device double-counting, and never silently overwrite `source = 'manual'` entries.
* **ADR-008 (Pre-Validated Exclusive-Transaction Restore):** `backupService.ts` validates the full JSON payload in memory before touching SQLite, warns the user that restoring **replaces all existing data**, and runs all `DELETE`/`INSERT` queries inside `db.withExclusiveTransactionAsync(async (txn) => ...)` using the `txn` handle.
* **ADR-009 (Routes in Root `app/`, Not `src/app/`):** The SDK 58 default template puts Expo Router routes in `src/app/`. PulseLog keeps them in root `app/` as specified in `Architecture.md` §2; non-route code lives in `src/` and is imported via the `@/*` → `./src/*` path alias. Template demo screens, components, hooks and the `reset-project` script were not kept.
* **ADR-010 (Real-Timezone Date Tests):** `dateUtils.test.ts` runs under `jest/timezoneEnvironment.js` (jest-expo native env + `__setProcessTimezone`) so midnight/DST cases are tested in Asia/Kolkata, America/Los_Angeles and America/New_York regardless of the developer machine's timezone.
* **ADR-011 (Narrow DB Interfaces + Real SQLite in Jest):** Services take `DbConnection` / `DbExecutor` from `src/db/client.ts` (expo-sqlite's `SQLiteDatabase` satisfies them; `tsc` checks this via `onInit={initializeDatabase}`). Jest runs them against `src/test-utils/nodeSqliteDatabase.ts`, a wrapper over Node's built-in `node:sqlite` (no extra dependency) that mirrors expo-sqlite: foreign keys start off, and exclusive transactions use a second connection. Test helpers live outside `__tests__/` so Jest doesn't treat them as suites.
* **ADR-012 (Versioned Migrations):** `schema.ts` exports `MIGRATIONS` (append-only) and `SCHEMA_VERSION = MIGRATIONS.length`. `initializeDatabase()` runs pending migrations one per exclusive transaction and bumps `PRAGMA user_version` inside it, and refuses databases newer than the app. Schema v1 = Architecture.md §3 plus indexes on `workouts(workout_date)`, `workout_sets(workout_id)` and `meal_logs(logged_date)`.
* **ADR-013 (Profiler Keeps Timings In Memory):** `profileQuery(label, fn)` records `performance.now()` durations (capped at 1,000) including failures; `summarizeQueryTimings()` gives per-label count/min/median/p95/max over successful runs for pasting into §4 after device runs. Nothing is logged automatically.
* **ADR-014 (Targets Service Shape):** `targetsService.ts` uses the `user_targets` column names as `TargetKey`s and `TARGET_FIELDS` (label, unit, min) as the single source for UI order and validation. `setTargets()` upserts only the keys provided (`null` clears one), validates every value before writing (whole numbers; calories/steps > 0, macros ≥ 0), and throws `TargetValidationError` with the failing key. `parseTargetInput()` maps an empty field to `null`, which is how the UI expresses "no target". "Clear all targets" sets every column to `null`; it never touches logs.
* **ADR-015 (Screen Tests Use the Real Test DB):** Screen tests render with `@testing-library/react-native` and mock only `expo-sqlite`'s `useSQLiteContext` (returning a `NodeSqliteDatabase`) and `expo-router`'s `router`, so taps hit real service and SQL code (see `targetsModal.test.tsx`).
* **ADR-016 (Calendar-Window Moving Average):** `computeWeightTrend()` averages every log dated within the 7 calendar days ending on each log's date (inclusive), not the last 7 entries, and reports `sampleCount` so sparse windows are visible. It is a pure function over `{loggedDate, weightKg}`; date math uses `addDaysToLocalDate()` / `diffLocalDays()` (UTC-based, DST-safe) in `dateUtils.ts`.
* **ADR-017 (Weight Log Semantics):** One weight per `logged_date`. `saveWeightLog()` upserts (logging the same date again replaces it; the UI warns first). `updateWeightLog()` edits date and/or weight and throws `DuplicateWeightDateError` rather than silently merging onto another date's entry. Weights are rounded to 0.1 kg and must be in (0, 500] kg. The Trends screen also blocks future dates (UI-only rule, so backups and tests can still write any valid date). `getLatestWeightOnOrBefore()` is the single prior-or-same-day lookup Task 1.5 must use (ADR-004).
* **ADR-018 (Chart Library: react-native-gifted-charts via Deep Import):** victory-native 43 requires `react-native-skia >=2.15.1`, but the latest `@shopify/react-native-skia` is 2.14.0, so it was skipped. gifted-charts' package root loads BarChart, which throws at import time unless `expo-linear-gradient`/`react-native-linear-gradient` is installed, so `WeightTrendChart` imports `react-native-gifted-charts/dist/LineChart` directly (no `exports` map blocks it). Per-point `spacing` = days to the next log × 16 px gives a true time axis; axis/spacing math lives in the pure `weightChartData.ts`. Re-check the deep import path when upgrading gifted-charts (`weightChart.test.tsx` renders the real chart and will fail if it moves).
* **ADR-019 (Tabs via `expo-router/js-tabs`):** Bottom tabs use the JS `Tabs` from `expo-router/js-tabs` (the root `Tabs` export is deprecated in SDK 58) with labels only (no icon dependency) and solid theme colors. Today's placeholder moved to `app/(tabs)/index.tsx`; Workouts and Nutrition tabs are added in Tasks 1.5/1.6.

## 3. Known Platform Gotchas
* **UTC `.toISOString()` Midnight Bug:** Never call `new Date().toISOString().slice(0, 10)` to generate `logged_date`. In timezones ahead of or behind UTC, logging at 11:30 PM or 1:00 AM records the wrong calendar day. Always use `toLocalDateString()`.
* **SQLite Transaction Handle Trap:** Inside `db.withExclusiveTransactionAsync(async (txn) => { ... })`, calling `db.runAsync(...)` instead of `txn.runAsync(...)` can deadlock or bypass the transaction scope. Always invoke queries on `txn`.
* **SQLite Foreign Keys:** `PRAGMA foreign_keys = ON;` must run every time the database connection opens in `src/db/client.ts` so deleting a workout cascades to `workout_sets`.
* **Exclusive Transactions Ignore Foreign Keys (verified in expo-sqlite 58 source):** `withExclusiveTransactionAsync` opens a NEW native connection (`useNewConnection: true`) and runs `BEGIN` before the callback. `PRAGMA foreign_keys` is off on that connection and is a no-op inside a transaction, so on `txn` orphan inserts succeed and `ON DELETE CASCADE` does not fire. Inside exclusive transactions, delete `workout_sets` before `workouts` explicitly and call `assertForeignKeysValid(txn)` before returning (it throws → rollback). Covered by `dbSchema.test.ts`.
* **Exclusive Transactions Are Not Supported on Web:** `initializeDatabase()` uses them for migrations, so the app does not start on web. iOS/Android only.
* **Android Health Connect Duplicate Class Error:** When starting Milestone 2, only install `react-native-health-connect`. Do not install the deprecated `expo-health-connect` wrapper.
* **Jest Sandboxes `process.env`:** Assigning `process.env.TZ` inside a test only changes Jest's sandbox copy and never reaches V8, so dates keep the machine's timezone. Use `__setProcessTimezone()` from `jest/timezoneEnvironment.js` (opt in with a `@jest-environment` docblock).
* **ICU Timezone Aliases:** `Intl...resolvedOptions().timeZone` may return a legacy alias (`Asia/Kolkata` → `Asia/Calcutta`). Assert on offsets/dates, not zone names.
* **Git Bash on Windows:** MSYS strips a `TZ=...` prefix before launching Windows programs, and `npx expo install ... "--" --dev` dropped `--dev` (packages landed in `dependencies`). Run TZ experiments from PowerShell and verify `package.json` after installing dev packages.
* **`jest.mock` Hoisting:** Factories are hoisted above `const mockX = ...`, so `jest.mock('expo-router', () => ({ router: mockRouter }))` captures `undefined`. Return the mock through a getter (`get router() { return mockRouter; }`). Use `mockReturnValueOnce` for per-test overrides; `jest.clearAllMocks()` does not reset return values.
* **`jest.mock` Factories Can't Use Imports:** Babel rejects factories that reference imported bindings (e.g. `Text`). Use `jest.requireActual('react-native')` inside the factory.
* **gifted-charts Timers in Jest:** `LineChart` schedules `setTimeout`s even with `isAnimated={false}`; they fire after teardown ("environment has been torn down"). Tests that render the real chart use fake timers and `act(() => jest.runOnlyPendingTimers())` before unmount; screen tests mock `WeightTrendChart`.
* **Alert Callbacks in Tests:** Spy on `Alert.alert`, then call the destructive button's `onPress` inside `await act(async () => ...)` to avoid "not wrapped in act" warnings.
* **RNTL v14 Is Async:** `await render(...)`, and use `userEvent.setup()` + `await user.type/press/clear(...)`.
* **Jest 30 Required:** jest-expo for SDK 58+ requires Jest 30; always install `jest`, `@types/jest` and `jest-expo` together via `npx expo install`.
